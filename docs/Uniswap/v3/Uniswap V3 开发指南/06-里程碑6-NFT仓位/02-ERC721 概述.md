# 02 ERC721 概述

原文：<https://learnblockchain.cn/article/23823?course_id=100>

这一节不是专门讲 Uniswap，而是补 ERC721 的基础。

先记住一句话：

```text
ERC721 是用 tokenId 表示一件独立资产的标准。
```

在这一章里，这件独立资产就是一个 V3 LP 仓位。

## ERC721 和 ERC20 的核心区别

ERC20 关注的是数量。

比如：

```text
我有 100 USDC
你有 50 USDC
```

每一个 USDC 都一样。

ERC721 关注的是编号。

比如：

```text
我拥有 tokenId = 7
你拥有 tokenId = 12
```

`7` 和 `12` 是两件不同资产。

所以 ERC721 不问“你有多少个完全相同的份额”，而是问：

```text
这个具体 tokenId 归谁？
```

## ERC721 最重要的几个概念

第一，`ownerOf(tokenId)`。

它回答：

```text
这个 NFT 当前属于谁？
```

第二，`balanceOf(owner)`。

它回答：

```text
这个地址一共有多少个 NFT？
```

注意它只返回数量，不告诉你具体有哪些 tokenId。

第三，`approve` 和 `getApproved`。

它们允许 NFT 拥有者授权某个地址操作某一个具体 tokenId。

第四，`setApprovalForAll`。

它允许用户授权某个 operator 管理自己所有 NFT。

第五，`transferFrom` 和 `safeTransferFrom`。

它们负责转移 NFT 所有权。

`safeTransferFrom` 会额外检查接收方合约是否支持接收 ERC721，避免 NFT 被转进不懂 NFT 的合约里。

## ERC721Metadata 是什么

ERC721Metadata 给 NFT 增加展示信息。

常见函数有：

```text
name()
symbol()
tokenURI(tokenId)
```

其中最重要的是 `tokenURI`。

它返回一段 metadata 地址或内容。

metadata 通常包含：

```text
name
description
image
attributes
```

前端、钱包、NFT 市场会读取这些信息，把 NFT 展示出来。

## tokenURI 和图片是什么关系

NFT 本体不是图片。

NFT 本体是链上的所有权记录。

`tokenURI` 只是告诉外部：

```text
这个 tokenId 应该怎么展示。
```

图片可以存在 IPFS，也可以存在中心化服务器，也可以像课程里一样链上动态生成 SVG。

对 V3 仓位 NFT 来说，图片只是仓位信息的可视化。

## OpenZeppelin 帮我们做了什么

ERC721 标准有很多细节。

比如：

- 转账前后余额怎么更新；
- 授权怎么检查；
- 安全转账怎么回调；
- tokenId 不存在时怎么处理；
- 事件怎么发。

手写容易出错。

所以项目通常直接继承 OpenZeppelin 的 ERC721 实现。

我们真正要关注的是：

```text
如何把 tokenId 和 Uniswap V3 仓位绑定起来。
```

## 人话版理解

ERC721 像产权证系统。

它不关心房子内部结构，也不关心房子值多少钱。

它只负责：

```text
7 号证归谁
谁被授权管理 7 号证
7 号证能不能转给别人
7 号证的展示资料在哪里
```

在 V3 里，房子就是 LP 仓位，产权证就是 NFT。

## 你要记住

- ERC721 用 `tokenId` 标识独立资产。
- `ownerOf` 查询某个 tokenId 的主人。
- `approve` 授权单个 NFT，`setApprovalForAll` 授权全部 NFT。
- `safeTransferFrom` 会检查合约接收方是否能接 NFT。
- `tokenURI` 是展示入口，不是 NFT 本体。
- OpenZeppelin 解决 ERC721 标准细节，我们只需要把业务状态接上去。
