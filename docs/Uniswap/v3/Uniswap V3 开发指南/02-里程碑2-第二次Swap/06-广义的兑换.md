# 06 广义的兑换

这一节是里程碑 2 的核心。

目标是：

> 把 `swap` 从“只会一个方向的示例函数”，升级成双向的、动态计算的 exact input swap。

## 新的 `swap` 参数

```solidity
swap(recipient, zeroForOne, amountSpecified, data)
```

只要理解两个参数就够了：

### `zeroForOne`

- `true`: `token0 -> token1`
- `false`: `token1 -> token0`

### `amountSpecified`

- 用户这次准备卖出的输入数量
- 本阶段实现的是 exact input，而不是 exact output

## 为什么叫“广义的兑换”

因为现在 swap 不再绑死在一个方向、一个写死金额上。  
它变成了一个通用框架：

- 方向可切换
- 输入量可变
- 输出量动态算

## swap 的最小执行心智模型

```text
读取当前价格和 tick
初始化剩余输入量
找到当前方向上的下一个初始化 tick
计算这一步最多能消耗多少输入、产出多少输出
更新价格、tick、累计输出
循环直到输入量处理完
结算 amount0 / amount1
先转出输出 token
再回调收回输入 token
```

## 这里最重要的内部函数

### `computeSwapStep`

它负责解决一个局部问题：

> 在当前价格到目标价格这一步里，能吃掉多少输入，给出多少输出？

你可以把整个 swap 看成很多 `step` 拼起来的结果。

## `amount0` / `amount1` 的符号怎么记

从池子视角看：

- 正数：池子收到
- 负数：池子付出

所以：

- `token0 -> token1` 时，`amount0 > 0`，`amount1 < 0`
- `token1 -> token0` 时，`amount1 > 0`，`amount0 < 0`

## 安全性靠什么保证

和前一里程碑一样，不是靠“信任用户”，而是靠：

1. 池子先转出输出 token
2. 回调调用方，要求它支付输入 token
3. 回调结束后检查余额是否到账
4. 没到账就 `revert`

所以 swap 的安全根基是：

> 回调后的余额验证 + 交易原子性

## 这节真正想让你学会什么

- swap 的本质是“输入推动价格移动，再从价格差反推出输出”。
- 双向交易靠 `zeroForOne` 控制。
- exact input 模式下，用户指定的是输入，不是输出。
- 代码结构已经在为跨 tick swap 铺路。
