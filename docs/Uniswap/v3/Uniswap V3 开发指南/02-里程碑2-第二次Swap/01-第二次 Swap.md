# 01 第二次 Swap

这一里程碑的目标只有一句话：

> 把“能演示一次 swap 的玩具版”，升级成“更接近真实 DEX 的可用版”。

## 这阶段到底新增了什么

和里程碑 1 相比，这次有 4 个关键升级：

1. 不再硬编码结果，开始在 Solidity 里实时算数。
2. swap 不再只能一个方向，而是支持双向交易。
3. 前端可以先拿报价，再决定要不要成交。
4. UI 不再写死金额，而是允许用户输入任意数量。

## 你这阶段要真正学会的内容

- 知道 `zeroForOne` 决定交易方向。
- 知道 V3 的报价不能只靠简单公式，必须模拟真实 swap。
- 知道 `mint` 和 `swap` 都要从“硬编码”升级成“动态计算”。
- 知道这阶段仍然只处理单区间成交，完整跨 tick 是下一里程碑。

## 这 8 节课的作用

1. `第二次 Swap`
作用：告诉你这一阶段整体要解决什么问题。

2. `输出数量计算`
作用：先补齐“卖 token0 时怎么计算价格和输出”。

3. `Solidity 中的数学`
作用：把 Python 里的数学，安全地搬到 Solidity。

4. `Tick Bitmap Index`
作用：为后面“快速找到下一个已初始化 tick”做准备。

5. `通用化 Minting`
作用：把 mint 从写死数量，改成链上动态计算。

6. `广义的兑换`
作用：把 swap 升级成真正的双向 exact input swap。

7. `Quoter 合约`
作用：实现“不成交，只报价”。

8. `Web 用户界面`
作用：让前端支持双向交易和实时报价。

## 这阶段的学习主线

按这个顺序理解最顺：

1. 先看数学为什么要补齐。
2. 再看 Solidity 里怎么安全实现这些数学。
3. 再看 mint 和 swap 如何改造成通用版。
4. 最后看 Quoter 和前端如何接起来。

## 学完后的最低标准

如果你真的学会了，这 4 个问题你应该能回答：

- 为什么这阶段必须引入 `zeroForOne`？
- 为什么 Quoter 不是普通 `view` 函数？
- 为什么 Solidity 里做除法和舍入要格外小心？
- 为什么这一版已经像真实 DEX，但还不算完整 V3？
