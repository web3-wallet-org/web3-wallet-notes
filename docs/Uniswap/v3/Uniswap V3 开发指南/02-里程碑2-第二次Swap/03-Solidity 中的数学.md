# 03 Solidity 中的数学

这一节不是在讲“复杂数学”，而是在讲：

> 同样的公式，搬到 Solidity 后为什么会突然变难。

## 难点只有 3 个

### 1. Solidity 没有浮点数

所以像 `sqrt(P)` 这种值，不能直接按小数算。  
V3 的做法是使用定点数格式：`sqrtPriceX96`。

你可以把它理解成：

- 真实值先乘一个很大的系数
- 再以整数形式存储和计算

## 2. 除法会截断

Solidity 整数除法会直接向下取整。  
这意味着：

- 不同舍入方向会影响最终 amountIn / amountOut
- 错误的舍入会让池子多给钱或少收钱

## 3. 乘法可能溢出

像下面这种表达式，链上要非常小心：

```text
amountIn * sqrtPriceX96
```

数一大就可能溢出，所以实现里会用：

- `mulDiv`
- `mulDivRoundingUp`
- 等价变形公式

## 这一节的核心工程观念

链上数学不是“把公式翻译成代码”就结束了，而是还要同时保证：

- 正确
- 不溢出
- 舍入方向合理
- gas 不离谱

## 你要记住的几个工具函数

### `mulDiv`

作用：安全地做“先乘后除”。

### `mulDivRoundingUp`

作用：在需要向上取整的地方，避免少算。

### `divRoundingUp`

作用：在协议需要保守处理时，保证结果向上取整。

## 这一节最重要的结论

- Python 里能算，不代表 Solidity 里能直接照抄。
- 定点数、舍入、溢出，是链上数学的三座大山。
- 后面 `mint` 和 `swap` 的所有动态计算，都建立在这些安全数学函数上。
