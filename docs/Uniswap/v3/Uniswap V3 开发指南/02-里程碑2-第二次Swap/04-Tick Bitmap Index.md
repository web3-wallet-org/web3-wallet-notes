# 04 Tick Bitmap Index

这一节解决的是性能问题：

> 池子怎么快速找到“下一个有流动性的 tick”？

## 为什么需要它

在 V3 里，不是每个 tick 都有流动性。  
只有用户真的在某个区间提供过流动性，那个 tick 才算“已初始化”。

如果每次 swap 都线性扫描整个价格轴，成本会非常高。

所以需要一个索引结构：

- 哪些 tick 已初始化
- 能快速找到下一个初始化 tick

这就是 `TickBitmap`。

## 你可以怎么理解 bitmap

把它想成一排开关：

- `1` 表示这个 tick 已初始化
- `0` 表示这个 tick 没有初始化

这样就能用位运算快速查找，而不是一个个遍历。

## 这一节最重要的两个操作

### `flipTick`

作用：某个 tick 从未初始化变成初始化，或者反过来时，切换它对应的 bit。

### `nextInitializedTickWithinOneWord`

作用：给定当前 tick 和方向，找到下一个已初始化 tick。

这是后面 swap 循环的基础。

## 为什么这一节出现在里程碑 2

因为作者已经在为下一阶段的跨 tick swap 铺路了。  
虽然你现在还没完整跨多个区间成交，但结构已经开始往那个方向搭。

## 你真正要学会什么

- tick 信息不只存在 `mapping(int24 => Tick.Info)` 里。
- 还需要一个“是否已初始化”的快速索引。
- bitmap 的意义不是数学，而是性能和可扩展性。

## 一句话总结

`Tick.Info` 负责存细节，`TickBitmap` 负责快速检索。
