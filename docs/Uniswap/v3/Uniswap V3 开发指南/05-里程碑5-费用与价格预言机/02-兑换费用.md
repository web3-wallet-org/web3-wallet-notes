# 02 兑换费用

原文：<https://learnblockchain.cn/article/23818?course_id=100>

这一节是第 5 章最绕的一节。

先把核心压成一句话：

```text
Pool 不会每次 swap 都挨个更新所有 LP 仓位，而是用全局费用 + tick 边界费用，等用户操作仓位时再算他该拿多少。
```

这就是费用系统的关键。

## 这节在解决什么

每次 swap 都会产生费用。

问题是：这些费用应该分给哪些 LP？

答案不是“所有 LP 平分”，而是：

```text
分给当前价格实际经过的流动性范围里的 LP。
```

比如某个 LP 提供的范围是：

```text
1000 USDC/ETH 到 2000 USDC/ETH
```

如果当前价格一直在这个范围外，那它没有参与交易，不应该赚这段时间的费用。

所以我们要精确记录：

```text
某个仓位范围内部，累计产生了多少费用。
```

## 为什么不能每次都更新所有仓位

最直接的做法是：

```text
每次 swap 后，遍历所有 LP 仓位，按比例更新每个人赚到的费用。
```

但链上不能这么干。

因为仓位数量可能非常多，遍历所有仓位 gas 会爆炸。

Uniswap V3 的做法更聪明：

```text
swap 时只更新少量全局变量和被跨过的 tick。
等某个 LP 自己 mint、burn、collect 时，再按公式算他赚了多少。
```

这是一种懒记账。

## 三层费用账本

这一节最重要的是理解三层账本。

第一层：全局费用。

```text
feeGrowthGlobal0X128
feeGrowthGlobal1X128
```

它们表示：

```text
每 1 单位流动性，历史上一共赚了多少 token0 / token1 费用。
```

注意它不是总费用，而是“按每单位流动性摊开之后的费用”。

第二层：tick 外部费用。

```text
feeGrowthOutside0X128
feeGrowthOutside1X128
```

每个 initialized tick 会记录：

```text
这个 tick 外面累计了多少费用。
```

tick 是价格范围的边界。知道边界外面的费用，就能反推某个范围里面的费用。

第三层：仓位内部费用。

```text
feeGrowthInside
```

它不是长期单独存一份，而是通过下面公式算出来：

```text
范围内费用 = 全局费用 - lower tick 下方费用 - upper tick 上方费用
```

## 为什么 tick 要记录 outside

一个 LP 仓位由两个 tick 决定：

```text
lowerTick
upperTick
```

它想知道自己范围内部赚了多少费用。

如果我们知道：

```text
全局一共赚了多少
lowerTick 下方赚了多少
upperTick 上方赚了多少
```

那中间范围自然就是：

```text
内部费用 = 全局 - 下方 - 上方
```

所以 tick 记录 outside，本质是为了以后能快速切出某个价格范围内部的费用。

## swap 时费用怎么收

费用从输入 token 里扣。

如果用户输入 1000，并且手续费是 0.3%，那真正进入价格计算的不是 1000，而是：

```text
1000 * (1 - 0.3%)
```

剩下那 0.3% 留在池子里，变成 LP 的费用收入。

代码里会在 `SwapMath.computeSwapStep` 中计算：

```text
amountRemainingLessFee
feeAmount
```

也就是先扣费用，再用扣完费用后的金额推动价格。

## 为什么费用要除以 liquidity

swap 产生的费用是一个总数，比如：

```text
本步收了 3 USDC 费用
```

但不同 LP 的流动性份额不同，所以要换成：

```text
每 1 单位流动性赚了多少费用
```

也就是：

```text
feeAmount / 当前 liquidity
```

这样之后某个仓位只要拿自己的 `liquidity` 乘上费用增长量，就知道自己该得多少。

## 跨 tick 时为什么要更新费用

价格跨过 tick，意味着进入或离开某个 LP 的价格范围。

这时 tick 必须更新自己的 outside 费用。

可以把它理解成：

```text
价格跨过边界时，在边界处拍一张费用快照。
```

后面计算某个仓位内部费用时，就靠这些边界快照判断哪些费用属于范围内，哪些费用属于范围外。

## LP 什么时候真正拿到费用

费用不是 swap 时立刻打给 LP。

swap 只是在池子里记账。

LP 真正更新自己费用时机通常是：

```text
mint
burn
collect
```

尤其是 `burn` 和 `collect`：

- `burn`：减少流动性，同时把可领取数量记到 `tokensOwed`。
- `collect`：真正把 `tokensOwed` 转给用户。

所以：

```text
burn 是把仓位里的权益结算出来。
collect 是把结算出来的钱取走。
```

如果只想收费用但不移除流动性，可以 burn 0，让合约刷新费用账本，再 collect。

## fee 和 tickSpacing 的关系

这一节也把 Pool 参数从只看 `tickSpacing` 调整成看 `fee`。

Factory 会维护：

```text
fee -> tickSpacing
```

例如：

```text
500  -> 0.05%
3000 -> 0.3%
```

真实含义是：

```text
不同手续费等级，对应不同 tickSpacing。
```

稳定币池通常费用低、tickSpacing 小；波动大的资产池费用高、tickSpacing 大。

## 人话版理解

想象一个商场按楼层收租。

每次有顾客在某一层消费，只有那层正在营业的店铺能分钱。

商场不会每来一个顾客就挨个给店铺转账。它只维护：

```text
全商场累计收入
每层边界外面累计收入
每家店上次结算时的收入快照
```

等某家店要结算时，再用这些账本算它这段时间该拿多少。

Uniswap V3 费用系统也是这个味道。

## 你要记住

- swap 费用来自输入 token。
- 费用只属于当前被激活的流动性范围。
- 不会每次 swap 都更新所有 LP 仓位，这是为了省 gas。
- `feeGrowthGlobal` 表示每单位流动性累计费用。
- tick 的 `feeGrowthOutside` 是计算仓位内部费用的边界快照。
- 仓位费用大致等于：全局费用减去范围外费用。
- `burn` 负责结算，`collect` 负责提款。
