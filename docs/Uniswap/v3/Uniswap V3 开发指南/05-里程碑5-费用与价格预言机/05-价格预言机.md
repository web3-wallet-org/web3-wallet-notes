# 05 价格预言机

原文：<https://learnblockchain.cn/article/23816?course_id=100>

这一节讲 Uniswap V3 的价格预言机。

先把核心压成一句话：

```text
Pool 记录历史 tick 累积值，外部用两个时间点的差值算出一段时间的平均价格。
```

它不是去链下抓价格，而是把 Pool 自己的交易价格变成可读取的历史数据。

## 这节在解决什么

很多链上协议需要价格。

比如借贷协议要知道：

```text
ETH 现在值多少 USDC？
```

最危险的做法是直接读某个 Pool 的当前价格。

因为当前价格可以被一笔大交易临时推歪。

更稳的做法是读一段时间的平均价格：

```text
过去 10 分钟 ETH/USDC 的平均价格是多少？
```

这就是 TWAP。

## Uniswap 预言机和 Chainlink 的区别

Chainlink 这类预言机通常是外部网络把链下价格喂到链上。

Uniswap 预言机不是这样。

它的逻辑是：

```text
既然交易都在 Pool 里发生，那 Pool 的价格历史本身就是链上数据。
```

所以 Uniswap 不需要信任某个外部 API。

但它也不是万能的。Pool 流动性越深、套利越充分，价格越可靠。流动性很差的池子，预言机质量也会差。

## 为什么记录 tick 而不是普通价格

Uniswap V3 内部大量使用 tick。

tick 本质上是价格的对数表示：

```text
price = 1.0001 ^ tick
```

V3 预言机记录的是：

```text
tickCumulative
```

也就是：

```text
历史上每一秒 tick 的累加值
```

如果我们拿两个时间点的 `tickCumulative` 相减，再除以时间差，就能得到这段时间的平均 tick。

再把平均 tick 转回价格，就得到时间加权平均价格。

## TWAP 的公式怎么理解

假设有两个时间点：

```text
t1
t2
```

分别读到：

```text
tickCumulative(t1)
tickCumulative(t2)
```

平均 tick 就是：

```text
(tickCumulative(t2) - tickCumulative(t1)) / (t2 - t1)
```

人话版就是：

```text
这段时间里，价格大部分时间停在哪里，平均 tick 就更接近哪里。
```

这比只看最后一秒的价格稳很多。

## Observation 是什么

`Observation` 是一个历史记录槽。

它主要存：

```text
timestamp
tickCumulative
initialized
```

也就是：

```text
这个观察值是什么时间记录的
当时累计 tick 到多少
这个槽有没有启用
```

Pool 里有一个固定长度的 observation 数组，最多可以支持很多历史记录。

但默认不会一开始全部启用，因为写存储很贵。

## cardinality 是什么

`observationCardinality` 表示当前启用了多少个观察值槽位。

`observationCardinalityNext` 表示下一步最多可以扩到多少。

人话版：

```text
cardinality 是历史记录容量。
```

容量越大，能保留的历史越长，但写入和初始化成本也越高。

任何人都可以调用函数增加容量，但要自己付 gas。

## 写入观察值的时机

Pool 会在 swap 改变价格时尝试写 observation。

但同一个区块里不会每次 swap 都写。

如果当前区块已经写过 observation，就跳过。

这样做有两个意义：

1. 省 gas。
2. 减少区块内临时操纵价格对预言机的影响。

Uniswap 更关注一个区块开始前或上一个区块结束后的价格，而不是同一区块内部被反复推来推去的瞬时价格。

## 累积值怎么更新

新 observation 的 tickCumulative 大致是：

```text
上一次 tickCumulative + 当前 tick * 时间间隔
```

比如上一次记录后过了 10 秒，这 10 秒 tick 一直是 200：

```text
新增累计值 = 200 * 10
```

这就是“时间加权”的来源。

价格停留时间越长，对平均值影响越大。

## 读取观察值为什么复杂

因为 observation 数组是环形的。

容量满了以后，新记录会覆盖最老记录。

所以数组里的物理顺序不一定等于时间顺序。

另外，不是每个时间点都有 observation。某些区块没有 swap，就不会写记录。

所以读取时要做几件事：

```text
找到目标时间点前后的观察值
如果刚好没有，就插值
如果数组环绕了，还要正确处理顺序
```

这就是为什么原文后面会讲二分搜索。

但你学习时先不用被二分搜索绕进去，先抓住目标：

```text
为了得到某个 secondsAgo 对应的 tickCumulative。
```

## 人话版理解

预言机像给价格做行车记录仪。

它不是每一秒拍一张高清照片，而是在关键时间点存一个里程表：

```text
到现在为止，tick 累计走了多少
```

你想知道过去 30 分钟平均速度，就拿现在里程表减去 30 分钟前里程表，再除以时间。

Uniswap V3 想知道过去 30 分钟平均价格，也是同一个思路。

## 你要记住

- Uniswap V3 预言机记录的是 tick 累积值。
- TWAP 用两个时间点的累计值差除以时间差。
- `Observation` 是历史价格记录槽。
- observation 数组是环形缓冲区，满了会覆盖旧记录。
- `observationCardinality` 是可用观察值容量。
- 同一区块通常只写一次 observation，降低区块内操纵影响。
- 读取历史点可能需要插值和二分搜索。
