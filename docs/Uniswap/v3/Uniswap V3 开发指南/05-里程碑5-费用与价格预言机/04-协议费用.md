# 04 协议费用

原文：<https://learnblockchain.cn/article/23817?course_id=100>

这一节讲的是 Uniswap 的协议收入机制。

先记住一句话：

```text
协议费用不是额外向用户收费，而是从 LP 的 swap 手续费里切出一小部分给协议。
```

课程里为了简洁没有把它写进代码，只是解释真实 Uniswap 是怎么设计的。

## 这节在解决什么

前面实现的费用全部给 LP。

也就是：

```text
交易者付费 -> LP 收益
```

那协议本身怎么赚钱？

Uniswap V3 的设计里有一个开关：

```text
协议可以从 swap fee 中拿一部分。
```

比如用户付了 0.3% swap fee，这 0.3% 不一定全部给 LP，协议可以从这笔 fee 中抽走 1/4 到 1/10。

## 协议费用和 swap 费用的区别

swap 费用是交易者付的总手续费。

协议费用是从 swap 费用里拆出来的一部分。

可以这样看：

```text
用户付 swap fee
swap fee 先产生
其中一部分进入 protocolFees
剩下部分进入 LP 的 feeGrowthGlobal
```

所以协议费用不会改变用户付费入口，它只是改变这笔费用在 LP 和协议之间的分配。

## 为什么协议费用不是默认开启

真实 Uniswap 的协议费用机制长期是治理可控的。

它关系到 LP 收益和协议收入之间的平衡。

如果协议抽太多，LP 收益下降，流动性可能流走。

如果协议完全不抽，协议本身没有直接收入。

所以这是治理层面的问题，不只是技术问题。

## feeProtocol 怎么存

真实 Uniswap 在 `slot0` 里存一个 `feeProtocol`。

它同时表示：

```text
token0 的协议费用比例
token1 的协议费用比例
```

因为两个方向的 swap 输入 token 可能不同，所以 token0 和 token1 可以分别配置。

为了省存储，两个值会被打包进一个 `uint8`：

```text
低 4 位存 token0 的 feeProtocol
高 4 位存 token1 的 feeProtocol
```

这是一种链上常见的省 gas 写法。

## 协议费用怎么计算

在每一步 swap 计算出 `feeAmount` 之后，如果协议费用开启，就从 `feeAmount` 中扣一部分出来。

大致逻辑是：

```text
protocolFee = feeAmount / feeProtocol
feeAmount -= protocolFee
```

剩下的 `feeAmount` 才进入 LP 的费用增长。

被扣出来的部分进入：

```text
protocolFees.token0
protocolFees.token1
```

取决于这次 swap 的输入 token 是 token0 还是 token1。

## 谁能收协议费用

真实设计里，只有 Factory owner 能调用 `collectProtocol`。

可以理解为：

```text
协议费用属于协议治理控制的账户，不属于普通 LP。
```

`collectProtocol` 会把已经累计的协议费用转给指定接收地址。

## 人话版理解

LP 手续费像店铺收入。

协议费用像商场抽成。

顾客付的是同一笔钱，但这笔钱内部会拆成两部分：

```text
大部分给店铺
一小部分给商场
```

商场抽成开不开、抽多少，不是每个店自己决定，而是商场规则决定。

## 你要记住

- 协议费用来自 swap fee，不是额外再向用户收一笔。
- 开启协议费用后，LP 实际拿到的费用会减少。
- token0 和 token1 可以分别设置协议费用。
- `feeProtocol` 用位运算打包存储，是为了省 gas。
- 协议费用累计在 `protocolFees`，由 Factory owner 收取。
- 本课程这一节主要讲机制，没有把协议费用写入简化实现。
