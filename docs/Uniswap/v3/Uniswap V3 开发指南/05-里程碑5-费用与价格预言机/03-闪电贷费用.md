# 03 闪电贷费用

原文：<https://learnblockchain.cn/article/23814?course_id=100>

这一节很短，核心也很直接：

```text
闪电贷不能白借，借多少就要还多少，并且额外还手续费。
```

前面我们实现过闪电贷，但那时只要求借款人在回调结束前把本金还回来。

这一节把它升级成真实 Uniswap 的逻辑：闪电贷也要按 Pool 的 fee 收费。

## 这节在解决什么

旧版闪电贷逻辑是：

```text
借出 amount0 / amount1
回调借款人
检查池子余额是否至少恢复到借出前
```

这只能保证本金还了。

新版逻辑要保证：

```text
池子余额 >= 借出前余额 + fee
```

也就是借款人必须还：

```text
本金 + 手续费
```

## fee 怎么算

闪电贷费用用和 swap 一样的 fee 参数。

如果借了 `amount0`，费用是：

```text
fee0 = amount0 * fee / 1e6
```

如果借了 `amount1`，费用是：

```text
fee1 = amount1 * fee / 1e6
```

这里 `fee` 的单位和前面一样：

```text
500  = 0.05%
3000 = 0.3%
```

## 为什么要向上取整

代码里用的是 `mulDivRoundingUp`。

意思是：

```text
只要理论上应该收一点点费用，就不能因为整数除法被抹成 0。
```

如果不用向上取整，小额闪电贷可能因为精度问题不用付费。

这对协议来说是不合理的。

## flash 流程

新的流程可以看成：

```text
1. 计算 fee0 / fee1
2. 记录借出前的 token0 / token1 余额
3. 把 token 转给借款人
4. 调用借款人的 flash callback
5. callback 里借款人完成套利或其他操作
6. callback 结束后，Pool 检查余额
7. 如果余额不足本金 + 费用，回滚
```

注意，Pool 不关心借款人中间做了什么。

Pool 只关心最后：

```text
钱有没有回来，而且有没有多回来费用。
```

## 人话版理解

闪电贷像一秒钟的短租。

你可以把资产借出去，在同一笔交易里随便操作，但交易结束前必须还回来。

现在规则变成：

```text
只还本金不行，还要付服务费。
```

如果还少了，整笔交易回滚，就像从没发生过。

## 和 swap 费用的关系

这节的费用只是保证闪电贷也能给 Pool 带来收入。

它和 swap 费用用同一个 `fee` 参数，但实现路径不同：

- swap 费用在兑换计算中扣除；
- flash 费用在借款后通过余额检查收取。

## 你要记住

- 闪电贷必须在同一笔交易里还款。
- 新版闪电贷要求还本金加费用。
- 费用按 Pool 的 `fee` 参数计算。
- 费用计算要向上取整，避免小额借款逃费。
- Pool 不关心借款人怎么赚钱，只检查最终余额是否足够。
