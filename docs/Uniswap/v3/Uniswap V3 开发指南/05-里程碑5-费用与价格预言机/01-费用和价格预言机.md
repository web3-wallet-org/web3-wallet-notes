# 01 费用和价格预言机

原文：<https://learnblockchain.cn/article/23815?course_id=100>

这一章加两个东西：

```text
交易费用 + 价格预言机
```

它们都建立在前面已经完成的 Pool、tick、跨 tick swap、多池交易之上，但重要性不一样。

费用是 DEX 的核心机制。没有费用，LP 没有收益，就不会愿意把资产放进池子里。

价格预言机更像附加能力。它不影响 swap 能不能成交，但可以让其他链上协议读取某个池子的历史平均价格。

## 这章在解决什么

前面的 Pool 已经会交易，但还缺一个关键现实问题：

```text
LP 为什么要提供流动性？
```

答案就是费用。

每次用户 swap，都从输入 token 里扣一小部分，留在池子里。后面 LP 移除流动性或收取费用时，可以按自己贡献的流动性份额拿走这些费用。

这章还会补价格预言机：

```text
Pool 不只记录当前价格，还记录历史价格变化。
```

这样别的合约可以问：

```text
过去 30 分钟平均价格是多少？
```

而不是只相信当前一瞬间的价格。

## 为什么费用和预言机放到这一章

因为它们都依赖前面的基础能力。

费用依赖：

- 当前可用流动性；
- LP 的价格范围；
- 价格跨 tick 时的范围切换；
- 仓位能被准确定位。

预言机依赖：

- 当前 tick；
- swap 时价格如何移动；
- 每次价格变化时能写入历史观察值。

如果前面的 Pool 还只是玩具版，这两件事就很难写对。

## 费用的人话理解

每个 Pool 像一条收费道路。

用户每次通过，都要交一点过路费。

但不是所有 LP 都能拿到这笔费。只有当前价格经过的那段路，也就是正在被交易使用的价格范围，才应该赚这笔钱。

如果你的流动性范围根本没被价格走到，你就没有参与这次交易，也就不该分这次费用。

所以费用系统要回答的问题是：

```text
某个 LP 的某个价格范围，在它真正参与交易期间，累计赚了多少费用？
```

## 价格预言机的人话理解

预言机不是 Pool 去外面抓价格。

Uniswap 的思路反过来：

```text
既然交易都在 Pool 里发生，那 Pool 自己的成交价格就可以作为价格来源。
```

但不能只看当前价格。当前价格很容易被一笔大交易临时推歪。

所以更可靠的方式是看一段时间内的平均价格：

```text
过去 10 分钟
过去 30 分钟
过去 1 小时
```

这就是 TWAP，时间加权平均价格。

## 这一章的主线

这一章可以分成两条线看。

第一条线是 LP 收益：

```text
swap 收费
记录每单位流动性赚了多少
跨 tick 时记录费用边界
LP burn / collect 时拿走费用
```

第二条线是价格记录：

```text
swap 改变价格
Pool 写入 observation
observation 存 tickCumulative
外部按两个时间点计算平均 tick
平均 tick 再换算成平均价格
```

## 你要记住

- 费用是激励 LP 的核心机制。
- swap 费用来自输入 token。
- 只有被价格实际用到的流动性范围，才会赚取 swap 费用。
- 预言机不是外部报价，而是 Pool 自己记录历史价格。
- Uniswap V3 预言机记录的是 tick 累积值，而不是普通价格累积值。
- 当前价格容易被操纵，TWAP 更适合作为外部协议参考价格。

## 学完这节要能回答

- 为什么没有费用就很难有流动性？
- 为什么不是所有 LP 都能分到每一笔 swap 费用？
- 价格预言机为什么要看一段时间的平均价格？
- Uniswap 的价格预言机和 Chainlink 这类外部预言机有什么区别？
