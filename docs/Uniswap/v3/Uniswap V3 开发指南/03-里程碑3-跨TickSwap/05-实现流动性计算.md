# 05 实现流动性计算

原文：<https://learnblockchain.cn/article/23805?course_id=100>

这一节把“根据 token 数量和价格范围计算流动性”的逻辑搬到 Solidity 里，这样 Manager 合约就能自己算出要传给 Pool 的 `liquidity`。

## 这节在解决什么

前面我们已经会根据 `liquidity` 反推需要多少 `token0` 和 `token1`。

现在要反过来：

```text
用户给了 token0 数量、token1 数量、价格范围
=> 合约算出最多能铸造多少 liquidity
```

这一步是通用化 `mint` 的基础。

## 用 token0 计算流动性

如果只看 `token0`，流动性公式来自这一类关系：

```text
amount0 和 1 / sqrt(P) 的变化有关
```

整理后可以理解为：

```text
L = amount0 * sqrt(upper) * sqrt(lower) / (sqrt(upper) - sqrt(lower))
```

因为 Solidity 里乘法再除法容易溢出，所以实现时继续用 `PRBMath.mulDiv`。

## 用 token1 计算流动性

如果只看 `token1`，公式更直接：

```text
amount1 和 sqrt(P) 的变化有关
```

整理后可以理解为：

```text
L = amount1 / (sqrt(upper) - sqrt(lower))
```

在 Q64.96 定点数里，还要乘上对应的缩放因子，所以代码里同样用 `mulDiv` 做安全计算。

## 为什么有两个 L

你可能会疑惑：流动性不是一个 `L` 吗，为什么 `token0` 能算一个，`token1` 又能算一个？

原因是用户给的两个 token 数量不一定刚好匹配当前价格需要的比例。

如果用户给了很多 `token0`，但 `token1` 不够，那么真正能铸造的流动性受 `token1` 限制。

反过来也一样。

所以当价格范围包含当前价格时，要分别用 `token0` 和 `token1` 算一次流动性，然后取较小值。较小的那个才是公平可用的 `L`。

## `getLiquidityForAmounts` 的判断逻辑

最终函数要根据当前价格和用户价格范围的位置选择算法：

1. 当前价格低于用户区间：这个区间未来只需要 `token0`，用 `getLiquidityForAmount0`。
2. 当前价格高于用户区间：这个区间未来只需要 `token1`，用 `getLiquidityForAmount1`。
3. 当前价格在用户区间内：两种 token 都需要，分别计算后取较小值。

## 人话版理解

这节其实就是在算：

```text
用户这些钱，最多能买到多少“做市能力”？
```

如果用户的价格范围还没到当前价格，只需要一种 token。

如果用户的价格范围包含当前价格，就需要两种 token 搭配。哪种 token 少，哪种 token 就决定最终能铸造多少流动性。

## 你要记住

- `getLiquidityForAmount0` 用 `token0` 数量算流动性。
- `getLiquidityForAmount1` 用 `token1` 数量算流动性。
- `getLiquidityForAmounts` 会根据当前价格位置选择合适算法。
- 当前价格在区间内时，必须取两个结果里的较小值。

- 为什么当前价格在区间内时不能只用一种 token 计算？
- 为什么最终取较小的 `liquidity` 更公平？
