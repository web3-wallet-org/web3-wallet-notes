# 07 实现闪电贷

原文：<https://learnblockchain.cn/article/23806?course_id=100>

这一节实现一个简化版闪电贷。它不是跨 tick swap 的核心，但它让这个 Pool 更接近真实的 Uniswap V3。

## 闪电贷是什么

闪电贷就是：

```text
同一笔交易里借出，同一笔交易里还回来
```

不需要抵押，也不需要审批贷款流程。Pool 可以先把 token 借给调用者，但在函数结束前，调用者必须把钱还回来。

如果还不回来，整笔交易回滚，就等于什么都没发生。

## 为什么普通用户不能直接用

闪电贷必须在同一笔交易里执行“借钱、使用、还钱”这一整套逻辑。

普通钱包用户只能发起一个调用，没法在交易中间插入自定义逻辑。真正能使用闪电贷的一般是智能合约，因为合约可以在回调里写自己的操作。

## V2 和 V3 的区别

Uniswap V2 里，闪电贷是 swap 的一部分。你可以在 swap 中先拿走 token，但必须在同一笔交易里还回来。

Uniswap V3 把它拆成了独立的 `flash` 函数。

这个函数做的事情很直白：

1. 记录借出前 Pool 的 `token0` 和 `token1` 余额。
2. 把用户要借的 token 转给调用者。
3. 调用调用者合约的 `uniswapV3FlashCallback`。
4. 回调结束后检查 Pool 的余额是否不少于借出前。
5. 检查通过就完成，否则回滚。

课程里的版本重点是机制，所以只检查余额没有减少；真实协议还会计算并收取费用。

## 回调为什么重要

Pool 把钱借出去后，不能自己知道调用者要怎么使用这笔钱。

所以它只要求调用者实现一个回调函数。调用者可以在回调里做套利、还债、换仓等操作，但最后必须把借走的 token 还给 Pool。

回调里的 `data` 是自定义参数。调用者可以提前把要用的信息编码进去，Pool 原样传回。

## 人话版理解

闪电贷像一个“只看最终结果”的借款。

Pool 不关心你中间拿钱去做了什么，只关心函数结束时余额有没有回来。如果回来，就算成功；如果没回来，交易直接回滚。

## 你要记住

- 闪电贷必须在同一笔交易中偿还。
- 只有智能合约适合使用闪电贷，因为需要回调逻辑。
- V3 里闪电贷是独立的 `flash` 函数。
- Pool 的安全检查是：回调结束后余额必须够。
- 课程版本是简化实现，真实 V3 还会处理手续费。
