# 03 跨 Tick 交易

原文：<https://learnblockchain.cn/article/23800?course_id=100>

这一节是里程碑 3 的核心。它把 swap 从“只在当前价格区间内成交”，升级成“当前区间不够就跨到下一个区间继续成交”。

## 跨 tick 到底是什么意思

V3 里每个 LP 仓位都有 `lowerTick` 和 `upperTick`。当前价格落在哪些仓位里面，这些仓位的流动性就会合起来，成为当前可用的 `liquidity`。

交易会推动价格移动：

- 买 ETH，价格往上走；
- 卖 ETH，价格往下走；
- 价格碰到某个 tick 边界时，某些仓位会退出，某些仓位会进入。

跨 tick 的本质就是：价格走到边界了，Pool 要重新计算当前可用流动性，然后继续 swap。

## 为什么旧版会失败

旧版 `computeSwapStep` 默认当前区间的流动性足够吃完整个 `amountRemaining`。但如果用户交易金额很大，当前区间会先被吃完。

正确逻辑应该分两种情况：

1. 当前区间够用：价格停在区间内部，swap 完成。
2. 当前区间不够用：价格走到下一个 tick，吃完整段区间，剩余输入继续下一轮。

## `computeSwapStep` 怎么改

新的思路是先问一个问题：

```text
要把价格从当前位置推到下一个 tick，需要多少输入？
```

如果用户剩余输入大于等于这个数量，就说明当前区间会被吃完，下一步价格直接等于目标 tick 的价格。

如果用户剩余输入不够，就说明 swap 会停在当前区间内部，这时再用输入数量反推新的价格。

最后再用“实际走过的价格距离”重新计算：

- 本轮实际吃掉多少输入；
- 本轮实际输出多少 token。

## `swap` 循环怎么改

每一轮 swap 都做这几步：

1. 用 tick bitmap 找下一个已初始化 tick。
2. 计算当前价格到这个 tick 之间能成交多少。
3. 如果价格真的到达 tick 边界，就调用 `ticks.cross(nextTick)` 取得流动性变化。
4. 根据交易方向修正 `liquidityDelta` 的符号。
5. 更新当前 `state.liquidity`。
6. 如果还没成交完，就继续找下一个 tick。

这里最容易漏的是方向。

按约定，从左往右跨过 lower tick 会增加流动性，跨过 upper tick 会减少流动性。但如果 `zeroForOne = true`，价格是在往下走，所以流动性变化的符号要反过来。

## Tick 里为什么要分 `liquidityGross` 和 `liquidityNet`

`liquidityGross` 是这个 tick 上挂过的绝对流动性总量。它主要用来判断这个 tick 是否还需要保留在 bitmap 里。

`liquidityNet` 是跨过这个 tick 时，当前可用流动性应该加多少或减多少。它是有符号数，因为跨 tick 可能是增加，也可能是减少。

简单说：

- `liquidityGross` 管“这个 tick 有没有流动性”；
- `liquidityNet` 管“跨过去以后当前流动性怎么变”。

## 测试覆盖了什么

这一节的测试主要验证几种价格范围组合：

1. 单一价格范围：旧功能不能坏，小额交易应该停在区间内。
2. 完全重叠的多个范围：相当于同一段价格里流动性更深，价格移动更慢。
3. 连续价格范围：一个区间吃完后，能进入相邻区间继续成交。
4. 部分重叠范围：重叠区域流动性更深，价格在这段移动更慢，成交结果也不同。

## 人话版理解

跨 tick swap 就像开车过一段段限速不同的路。

每段路都有自己的“阻力”，也就是流动性。你给的输入金额越大，车开得越远。开到一段路的终点时，要重新看下一段路上有多少流动性，再决定继续走多远。

不能跳过没有流动性的空白区。如果前面没有下一段可用流动性，交易就没法继续。

## 你要记住

- swap 是循环执行的，每一轮只处理当前价格到下一个 tick 的一小段。
- 到达 tick 边界时必须更新 `liquidity`。
- `liquidityNet` 决定跨 tick 后流动性增加还是减少。
- 重叠区间流动性更深，价格更不容易被推动。
