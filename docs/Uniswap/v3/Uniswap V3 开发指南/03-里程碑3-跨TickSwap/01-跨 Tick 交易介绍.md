# 01 跨 Tick 交易介绍

原文：<https://learnblockchain.cn/article/23807?course_id=100>

这一节是里程碑 3 的开场。它要说的不是某个细节，而是这一整章要把前面那个“只能在一个价格区间里交易”的简化版 Pool，升级成更接近真实 Uniswap V3 的版本。

## 这节在解决什么

前两个里程碑里，swap 只能发生在当前价格所在的那一个区间里。只要这段区间里的流动性不够，程序就没法继续往下成交。

真实的 V3 不是这样。真实的 V3 里有很多 LP 放了不同的价格区间，价格会随着交易一路移动。当一个区间被吃完，价格就会碰到边界 tick，然后进入下一个区间继续成交。

所以这一章的目标就是：让交易可以跨过 tick，连续吃多个价格区间的流动性。

## 这一章会做哪些升级

1. `mint` 不再默认用户的价格范围一定包含当前价格，而是允许 LP 把流动性放在当前价格下面、里面或上面。
2. `swap` 不再假设当前区间一定够用，而是当当前区间流动性被吃完时，跨到下一个 tick。
3. 把“根据两个 token 数量计算流动性”的逻辑搬进 Solidity，方便 Manager 合约自己算 `liquidity`。
4. 给 `swap` 和 `mint` 加滑点保护，避免成交价格偏离用户预期太多。
5. 更新前端，让用户可以自己选价格范围、输入滑点。
6. 补一节定点数内容，解释价格、平方根价格和 tick 之间怎么转换。
7. 顺带实现闪电贷，让 Pool 更像真正的 V3。

## 人话版理解

可以把 V3 的流动性想成一条路上的很多收费站。

以前我们的车只能在当前收费站里面开，到了收费站边界就停了。现在要改成：

- 先在当前价格区间里成交；
- 如果输入金额还没用完，就把当前区间吃完；
- 到边界 tick 后，更新当前可用流动性；
- 进入下一个区间继续成交；
- 直到用户的输入用完，或者已经没有流动性可用了。

这一章的核心不是新增一个花哨功能，而是补上 V3 最重要的一块机制：价格范围之间的流动性切换。

## 你要记住

- `liquidity` 只表示“当前价格所在位置能立刻使用的总流动性”。
- LP 可以把流动性放在当前价格之外，那些流动性暂时是休眠的。
- 当价格跨过 tick，休眠流动性可能被激活，当前流动性也可能减少。
- 跨 tick swap 的本质就是：一段一段地吃流动性，每到边界就更新 `liquidity`。

## 学完这节要能回答

- 为什么前一版 swap 不算完整的 V3 swap？
- 为什么 `mint` 必须支持当前价格之外的范围？
- 为什么跨 tick 的关键是更新当前可用流动性？
