# 06 定点数的更多内容

原文：<https://learnblockchain.cn/article/23802?course_id=100>

这一节是补充内容，不是新的 AMM 机制。

它主要解决一个测试可读性问题：怎么在 Solidity 测试里，把人类好读的价格转换成 tick。

## 这节在解决什么

测试里如果一直写硬编码 tick，会很难读。

比如看到：

```text
85176
```

你很难马上知道它代表什么价格。

但如果测试里能写：

```text
tick(5000)
```

那就清楚很多：这就是价格 5000 附近的 tick。

问题是，tick 不是直接由价格得到的。

V3 的 tick 计算依赖 `sqrtPriceX96`，所以测试辅助函数需要先做这一步转换：

```text
普通价格 -> sqrtPriceX96 -> tick
```

也就是先把价格转换成 V3 能理解的 Q64.96 平方根价格，再调用 `TickMath.getTickAtSqrtRatio`。

## 为什么不能直接用普通平方根

Solidity 没有原生小数，也没有适合小数价格的原生平方根。

`PRBMath.sqrt(5000)` 会得到整数结果，精度不够。

`PRBMathUD60x18` 能处理 18 位十进制定点数，看起来更精确，但它和 Uniswap V3 用的格式不是一回事。

这里的关键不是“能不能开平方”，而是：

```text
开平方以后，结果必须是 TickMath 需要的 Q64.96 格式。
```

## Q64.96 和 UD60.18 的区别

Uniswap V3 的 `sqrtPriceX96` 是 Q64.96。

它是二进制定点数：

```text
实际值 * 2^96
```

`UD60.18` 是十进制定点数：

```text
实际值 * 10^18
```

这两个系统不能随便混用。它们都叫“定点数”，但缩放方式完全不同。

同一个实际数字，用 Q64.96 和 UD60.18 表示出来，底层整数完全不是一个含义。

## 用 ABDKMath64x64 做转换

课程里选择 `ABDKMath64x64`，因为它也是二进制定点数库。

它支持 Q64.64 的平方根。

转换思路是：

1. 把普通价格左移 64 位，变成 Q64.64。
2. 用 `ABDKMath64x64.sqrt` 求平方根。
3. 得到的结果还是 Q64.64。
4. 再左移 `96 - 64 = 32` 位，转成 Q64.96。
5. 把结果交给 `TickMath.getTickAtSqrtRatio` 得到 tick。

为什么要左移 32 位？

因为 Q64.64 和 Q64.96 都是二进制定点数。它们可以表示同一个实际值，只是小数部分的位数不同：

```text
Q64.64：实际值 * 2^64
Q64.96：实际值 * 2^96
```

Q64.96 比 Q64.64 多 32 位小数精度，所以要把 Q64.64 的结果左移 32 位：

```text
sqrtPriceX96 = sqrtPriceX64 << 32
```

## 人话版理解

这节的重点不是某个库，而是一个原则：

```text
做链上数学时，定点数格式必须对齐。
```

你不能拿十进制定点数的结果，直接塞进需要二进制定点数的函数里。数字看起来都很大，但含义完全不同。

所以这节不是在讲复杂业务逻辑，而是在给测试写一个更顺手、更不容易误读的价格转换工具。

## 你要记住

- `sqrtPriceX96` 是 Q64.96，不是普通小数。
- `PRBMathUD60x18` 是十进制定点数，不能直接当作 Q64.96 用。
- `ABDKMath64x64` 可以帮我们在测试里做二进制平方根。
- 这类工具主要是为了让测试更好读，不是主业务合约必需逻辑。
