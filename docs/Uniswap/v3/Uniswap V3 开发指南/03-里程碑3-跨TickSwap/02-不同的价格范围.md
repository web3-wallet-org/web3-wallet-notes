# 02 不同的价格范围

原文：<https://learnblockchain.cn/article/23801?course_id=100>

这一节讲 `mint` 的升级：LP 不一定非要把流动性放在当前价格附近，也可以放在当前价格下面或上面。

## 这节在解决什么

之前的 `mint` 写法默认价格范围一定包含当前价格，所以它总是：

- 根据当前价格算 `amount0`；
- 根据当前价格算 `amount1`；
- 直接增加 Pool 的全局 `liquidity`。

这个逻辑只适合“当前正在被使用的价格范围”。但真实 V3 允许三种范围：

1. 当前价格在范围内：这段流动性马上可用。
2. 整个范围在当前价格下方：现在用不上，等价格跌过去才会激活。
3. 整个范围在当前价格上方：现在也用不上，等价格涨过去才会激活。

## 价格范围为什么像限价单

不在当前价格里的流动性，暂时不会参与交易。它更像一个挂着等待触发的订单。

以课程里的 ETH/USDC 池为例，价格定义为：

```text
P = USDC / ETH
```

如果你把流动性放在当前价格下方，大致意思是：等 ETH 价格跌下来时，用 USDC 买 ETH。这个范围一开始只需要 USDC。

如果你把流动性放在当前价格上方，大致意思是：等 ETH 价格涨上去时，用 ETH 卖成 USDC。这个范围一开始只需要 ETH。

当价格完整穿过一个很窄的范围时，这段仓位会从一种 token 变成另一种 token。这就是为什么 V3 的窄范围流动性可以模拟限价单。

## `mint` 要怎么改

`mint` 需要先判断当前 tick 和用户区间的关系。

如果当前价格低于用户区间，也就是：

```text
currentTick < lowerTick
```

说明用户的范围在当前价格上方。这段流动性现在不会被用到，只需要 `token0`，并且不能增加全局 `liquidity`。

如果当前价格在用户区间里，也就是：

```text
lowerTick <= currentTick < upperTick
```

说明这段流动性马上可用。需要同时计算 `token0` 和 `token1`，并且要增加全局 `liquidity`。

如果当前价格高于用户区间，也就是：

```text
currentTick >= upperTick
```

说明用户的范围在当前价格下方。这段流动性现在也不会被用到，只需要 `token1`，同样不能增加全局 `liquidity`。

## 人话版理解

`liquidity` 这个全局变量不是“池子里所有 LP 的总流动性”，而是“当前价格这里能马上用的流动性”。

所以只有当前价格落在用户设置的区间里，`mint` 才能把这笔流动性加到全局 `liquidity`。如果用户把钱放在别的价格段，那笔钱现在是挂单状态，等价格移动过去再激活。

## 你要记住

- V3 的 LP 仓位有价格范围。
- 范围在当前价格外时，流动性是非活跃的。
- 非活跃流动性通常只由一种 token 组成。
- 只有包含当前价格的范围，才会影响当前 `liquidity`。
