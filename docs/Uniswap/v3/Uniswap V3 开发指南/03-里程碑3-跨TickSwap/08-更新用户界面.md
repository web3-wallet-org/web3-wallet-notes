# 08 更新用户界面

原文：<https://learnblockchain.cn/article/23804?course_id=100>

这一节把前面合约里的新能力接到前端：用户可以添加任意价格范围的流动性，也可以设置 swap 的滑点容忍度。

## 这节更新了什么

前端主要加两个功能：

1. 添加流动性的弹窗。
2. swap 时的滑点容忍度输入。

目标是去掉之前那些硬编码的流动性配置，让用户在页面里自己输入价格范围和数量。

## 添加流动性弹窗

用户输入的是价格，比如 lower price 和 upper price。

但合约要的是 tick，比如 `lowerTick` 和 `upperTick`。

所以前端需要做一层转换：

```text
用户输入价格
=> 转成 sqrtPriceX96
=> 再转成 tick
=> 调用 Manager.mint
```

课程里用官方 Uniswap V3 SDK 来做这件事：

- `encodeSqrtRatioX96`：把价格转成平方根价格格式。
- `TickMath.getTickAtSqrtRatio`：把平方根价格转成 tick。

这样用户不用理解 tick，只需要按价格填表单。

## Mint 的滑点处理

前端会根据滑点容忍度算出最低可接受数量。

课程里为了简单，把添加流动性的滑点写成 0.5%。

大致逻辑是：

```text
amountMin = amountDesired * (1 - slippage)
```

然后把 `amount0Desired`、`amount1Desired`、`amount0Min`、`amount1Min` 一起传给 Manager。

如果链上实际需要数量低于用户的最低要求，Manager 会回滚。

## Swap 的滑点处理

swap 的滑点保护不是用 `amountMin` 做的，而是用限制价格。

前端已经会调用 Quoter 预估交易结果。现在 Quoter 要额外返回：

- `amountOut`
- `sqrtPriceX96After`
- `tickAfter`

前端拿到 `sqrtPriceX96After` 后，根据用户输入的滑点容忍度，算出一个 `limitPrice`，再把它传给 Pool 的 `swap`。

这样实际 swap 时，价格最多只能走到用户允许的边界。

## 人话版理解

合约世界喜欢 tick、Q64.96、sqrt price。

用户世界只想填：

- 我要在哪个价格范围做市；
- 我要放多少 token；
- 我能接受多少滑点。

前端的任务就是把用户能理解的输入，翻译成合约能理解的参数。

## 你要记住

- 用户输入价格，合约需要 tick，前端负责转换。
- Uniswap V3 SDK 可以帮前端完成价格到 tick 的转换。
- 添加流动性用 `amountMin` 做滑点保护。
- swap 用 `sqrtPriceLimitX96` 做滑点保护。
- Quoter 不只给输出数量，还可以告诉前端交易后的价格位置。
