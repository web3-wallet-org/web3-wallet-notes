# 05 简化用户界面

原文：<https://learnblockchain.cn/article/23813?course_id=100>

这一节讲前端怎么配合多池交易。

先记住一句话：

```text
前端不再让用户手动选择 Pool，而是根据 token 自动找路径。
```

多池交易在合约层已经能跑了，但用户不可能自己手写：

```text
WETH, 60, USDC, 10, USDT, 60, WBTC
```

用户只会说：

```text
我要用 WETH 换 WBTC。
```

所以前端要帮用户找到一条可行路径，并把它编码成合约需要的 `Path`。

## 这节在解决什么

有了 `Factory` 和 `Path` 之后，前端可以简化很多东西：

1. 不需要存 Pool 地址。
2. 不需要让用户关心 token 顺序。
3. 单池和多池都可以统一成路径。
4. 改变交易方向时，可以直接反转路径。

但还有一个核心问题：

```text
如果两个 token 没有直接池，前端怎么知道应该从哪些中间 token 绕过去？
```

这就是 Router 要解决的事。

## Router 的本质

Router 不是合约里的 Pool。

在这一节里，它更像前端里的路径搜索器。

它拿到一堆已知交易对，比如：

```text
WETH/USDC
USDC/USDT
USDT/WBTC
DAI/USDC
```

然后当用户选择：

```text
WETH -> WBTC
```

Router 要找出一条可走的路线：

```text
WETH -> USDC -> USDT -> WBTC
```

## 为什么用图

这类问题最自然的模型是图。

可以这样理解：

```text
每个 token 是一个点
每个 Pool 是两个点之间的一条边
```

比如有一个 `WETH/USDC` 池，就相当于图里有：

```text
WETH <-> USDC
```

当所有池子都放进图里后，找兑换路径就变成：

```text
在图里从 tokenA 走到 tokenB
```

这就是路径搜索问题。

## AutoRouter 和简化 Router 的区别

真实 Uniswap 的 AutoRouter 很复杂。

它不只是找一条路径，还会考虑：

- 哪条路径价格更好；
- 哪条路径流动性更深；
- 要不要把一笔交易拆成多条路径；
- gas 成本和价格改善之间是否划算。

这一节不会实现那么复杂的版本。

这里的目标只是：

```text
找到一条能走的较短路径。
```

这对学习已经够了，因为重点是理解多池 swap 怎么被组织起来。

## A* 搜索在这里干什么

前端用图算法来找路径。

课程里用了 `ngraph.graph` 建图，用 `ngraph.path` 找路径。

你不用把 A* 算法细节背下来，只要知道它在这里的作用：

```text
给我起点 token 和终点 token，我返回一串中间 token。
```

比如返回：

```text
WETH, USDC, USDT, WBTC
```

然后前端再把边上的 `tickSpacing` 插进去，变成合约需要的路径：

```text
WETH, 60, USDC, 10, USDT, 60, WBTC
```

## 为什么边上要存 tickSpacing

因为 Pool 的身份不是只有两个 token，还包括 `tickSpacing`。

图里的边不只是表示：

```text
WETH 和 USDC 之间有池
```

还要知道：

```text
这个池的 tickSpacing 是多少
```

否则前端找到了 token 路线，也没法编码出正确的 `Path`。

## 人话版理解

前端 Router 就像地图导航。

用户输入：

```text
从 WETH 到 WBTC
```

Router 看地图：

```text
WETH 能到 USDC
USDC 能到 USDT
USDT 能到 WBTC
```

于是给出路线：

```text
WETH -> USDC -> USDT -> WBTC
```

然后前端把这条路线翻译成合约能读的 bytes path。

用户不用懂 Pool 地址、token 排序、tickSpacing 编码。前端负责把这些脏活做好。

## 你要记住

- 前端要把用户的 token 选择翻译成 `Path`。
- Pool 网络可以抽象成图：token 是点，Pool 是边。
- 路径搜索就是在图里从输入 token 找到输出 token。
- 边上必须带 `tickSpacing`，否则无法确定具体 Pool。
- 这里实现的是简化 Router，不是真实 Uniswap 的完整 AutoRouter。
- 单池和多池都可以统一走路径逻辑。

- 为什么不能让用户自己填路径？
- 为什么 Pool 网络适合用图来表示？
- Router 找到 token 路线后，为什么还要补 `tickSpacing`？
- 简化 Router 和真实 AutoRouter 差在哪里？
