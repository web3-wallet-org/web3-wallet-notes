# 里程碑 1：首次 Swap

## 🎯 本里程碑目标

在这个里程碑中，我们要完成一个**超级简化版的 Uniswap V3 池合约**，它能够：

1. ✅ 接收用户提供的流动性
2. ✅ 在一个价格范围内进行代币兑换（Swap）

为了让你更容易理解，我们先做一些**简化**：

| 简化项 | 说明 |
|-------|------|
| **单一价格范围** | 只在一个价格区间内提供流动性（后续会支持多个区间） |
| **单向交易** | 只允许用一个方向的兑换（比如用 USDC 买 ETH） |
| **手动计算数学** | 先用 Python 算好所有参数，再硬编码到 Solidity 中 |

## 📊 我们要构建的模型

让我们用一个具体的场景来建模：

### 场景设定

| 参数 | 值 |
|------|---|
| **交易对** | ETH/USDC |
| **x 储备** | ETH |
| **y 储备** | USDC |
| **当前价格** | 1 ETH = 5000 USDC |
| **价格范围** | 1 ETH = 4545 ~ 5500 USDC |
| **交易方向** | 用 USDC 购买 ETH |

### 可视化模型

想象一个价格范围，像一个"游泳池"：

| 价格 | 4545 | 5000 | 5500 |
|------|------|------|------|
| **位置** | 下限 | **当前价格** | 上限 |
| **流动性** | 起点 | 中间 | 终点 |

**我们的流动性覆盖整个范围：4545 → 5500**

当我们用 USDC 购买 ETH 时：
-  池子里的 ETH 减少
- 📈 池子里的 USDC 增加
- 📈 价格会从 5000 **略微上涨**

我们的目标是：**确保交易后的价格仍然在 4545-5500 这个范围内**。

## 🧮 为什么要先算数学？

在写代码之前，我们需要先搞清楚：

1. **需要多少流动性？**（L 值）
2. **需要多少 ETH 和 USDC？**（Δx 和 Δy）
3. **价格范围对应的 tick 是多少？**
4. **一次 Swap 会影响价格多少？**

### 计算流程

**Step 1**: 确定价格范围（4545-5500）  
**Step 2**: 计算 Tick 索引（84222, 85176, 86129）  
**Step 3**: 计算流动性 L（1517882343751509868544）  
**Step 4**: 计算 Token 数量（0.99 ETH, 5000 USDC）  
**Step 5**: 硬编码到 Solidity 合约

## 📝 实施策略

为了让你更容易理解，我们采用以下策略：

### 第一步：用 Python 计算

```python
# 示例：计算 tick
import math

def price_to_tick(p):
    return math.floor(math.log(p, 1.0001))

tick = price_to_tick(5000)
# 结果：85176
```

### 第二步：硬编码到 Solidity

```solidity
// 把计算好的值直接写入合约
int24 currentTick = 85176;
uint128 liquidity = 1517882343751509868544;
```

> **为什么这样做？**
> 
> 这样可以让我们**先专注于理解核心逻辑**，而不被复杂的数学库干扰。在后续的里程碑中，我们会逐步引入动态计算。
