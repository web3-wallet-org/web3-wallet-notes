
## 核心思路
私钥永远不离开 KMS，业务系统只调用 KMS 接口做签名，拿回签名结果后自己组装交易。

---

## 签名流程

1. 构造待签名的交易 hash（RLP 编码后 keccak256）
2. 调用 KMS 签名接口，传入 hash
3. KMS 返回 DER 格式的 ECDSA 签名（r, s）
4. 从签名结果中提取 r、s，计算 v
5. 用 r、s、v 组装完整交易，广播

---

## 关键工程细节

### DER 格式转换
KMS（如 AWS KMS）返回的签名是 DER 编码，不是原始的 r/s。需要手动解析：
- DER 结构：`30 len 02 rlen [r bytes] 02 slen [s bytes]`
- 提取 r、s 后各自补齐为 32 字节（不足左补零，开头多余的 00 需截掉）

### v 值计算
KMS 不返回 v，需要自己试出来：
- 用恢复出的公钥与账户地址对比，确定 v 是 27 还是 28（EIP-155 之前）
- EIP-155 之后：`v = chainId * 2 + 35 或 36`
- 做法：用 r、s 分别尝试 recovery_id = 0 和 1，哪个能还原出正确公钥，对应的就是正确 v

### s 值规范化（Low-S）
以太坊要求签名的 s 必须在曲线阶 n 的低半区（s <= n/2），否则节点会拒绝交易。
AWS KMS 有时返回 high-s，需要手动处理：
```
if s > n / 2:
    s = n - s
```

### 公钥与地址绑定
- 首次使用某个 KMS 密钥时，需要调用接口获取公钥，推导出 ETH 地址，存库绑定
- 推导方式：取公钥的 uncompressed 形式（04 开头 64字节），去掉 04 前缀，keccak256 后取后 20 字节

## AWS KMS 接入要点

### 密钥类型
必须选：`ECC_SECG_P256K1`（secp256k1 曲线，与 ETH 一致）
- 不能选 P256（NIST 曲线），那是不同曲线

### 最小权限 IAM 配置
热钱包服务只需要以下权限：
```json
{
  "Action": [
    "kms:Sign",
    "kms:GetPublicKey"
  ],
  "Resource": "arn:aws:kms:region:account:key/key-id"
}
```
绝对不要给 `kms:CreateKey`、`kms:DeleteKey`、`kms:DisableKey`。

### 调用延迟
AWS KMS 签名接口 P99 延迟约 50~100ms，比本地签名慢一个量级。
- 提币流程中这个延迟可以接受
- 如果批量构造交易，注意 KMS 的 TPS 限制（默认 1500 req/s per region）

### 限流与降级
- KMS 请求失败（ThrottlingException、KMSInternalException）需要重试，使用指数退避
- 不应该降级到本地签名，失败就失败，报警处理

## 多密钥管理

### 热钱包分组
- 不同币种或不同业务线可以使用不同 KMS 密钥
- 密钥 ARN 存数据库，与钱包地址一一对应

### 密钥轮换
- AWS KMS 支持自动轮换，但仅轮换对称加密密钥的底层材料
- 非对称密钥（ECC）不支持自动轮换，因为公钥地址会变
- ETH 地址绑定公钥，轮换 = 换地址，需要业务侧主动迁移资金

## 与 HSM / MPC 的对比

| 维度 | KMS | HSM | MPC |
|------|-----|-----|-----|
| 私钥单点风险 | 存在（云厂商托管） | 存在（物理设备） | 无（私钥分片，不聚合） |
| 运维复杂度 | 低 | 高 | 中 |
| 签名延迟 | 50~100ms | 1~10ms | 100~500ms（网络协议） |
| 适合场景 | 中小规模热钱包 | 合规要求高的机构 | 大规模交易所、高安全要求 |
| 信任假设 | 信任云厂商 | 信任硬件厂商 | 最小化信任 |

> 大多数中小型钱包项目用 KMS 足够，MPC 适合需要去除单点的高安全场景。

## 面试高频

**Q: 用 AWS KMS 签 ETH 交易，有哪些坑？**
三个必答点：① DER 格式需手动解析出 r/s；② v 值 KMS 不提供，需要两次 ecrecover 试出来；③ s 可能是 high-s，以太坊节点会拒绝，要做规范化处理。

**Q: KMS 密钥能轮换吗？**
对称密钥可以自动轮换底层材料，但非对称 ECC 密钥不支持自动轮换——因为轮换后公钥变了，ETH 地址就变了。要换地址只能手动迁移资金。

**Q: KMS 签名服务挂了怎么办，能降级到本地签名吗？**
不能。私钥从未存在业务服务器上，根本没有降级条件。正确做法是重试 + 告警 + 人工介入，降级到本地签名意味着私钥暴露，这是安全红线。

**Q: 为什么 IAM 权限不能给 kms:Decrypt？**
给了 Decrypt 权限，攻击者拿到加密私钥材料后就能解出明文私钥。签名服务只需要 Sign 和 GetPublicKey，最小权限原则。

**Q: KMS 和 CloudHSM 的本质区别是什么？**
KMS 是多租户托管服务，密钥以加密形式存在 AWS 基础设施中，理论上 AWS 可以访问；CloudHSM 是独占物理硬件，私钥物理上不能导出，即使 AWS 也无法拿到明文私钥。
