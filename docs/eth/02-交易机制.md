## 定义
交易是状态变更请求，由 EOA 发起，经签名后广播到网络。

<a id="sec-2"></a>
## 交易结构（EIP-1559）
- **nonce**：账户发出的第几笔交易，防止双花
- **to**：目标地址
- **value**：转账金额（wei）
- **data**：调用合约的 calldata，转账时为空
- **gasLimit**：愿意消耗的最大 gas
- **maxFeePerGas**：每单位 gas 愿付的最高价格
- **maxPriorityFeePerGas**：给 validator 的小费上限
- **chainId**：防止跨链重放

<a id="sec-3"></a>
## Gas 机制
- **base fee**：由协议动态调整，执行后销毁
- **tip（priority fee）**：支付给 validator，激励打包
- 实际费用 = gasUsed × (base fee + tip)，上限由 maxFeePerGas 控制

<a id="sec-4"></a>
## 签名流程
1. 构造交易对象
2. RLP 编码
3. keccak256 哈希
4. ECDSA 签名（得到 v, r, s）
5. 广播到网络

<a id="sec-5"></a>
## nonce 机制
- 每笔交易 nonce 必须严格递增，保证顺序执行
- 中间有缺口的 nonce 会导致后续交易全部 pending
- 并发场景下需要集中管理 nonce，避免冲突

<a id="sec-6"></a>
## 风险点
- gas 设置过低 -> 交易长期 pending 或被丢弃
- nonce 错误（重复或跳号）-> 交易失败或卡死
