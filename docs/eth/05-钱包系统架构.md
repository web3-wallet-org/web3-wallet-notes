
## 核心目标
安全管理用户资金，处理链上充提币，控制风险。

## 系统分层

### 钱包网关
- 对外暴露接口，接收充提币请求
- 鉴权、限流、路由到各子系统

### 充值系统
流程：监听新区块 -> 解析交易/logs -> 确认数达标 -> 入账

关键点：
- ETH 转账：直接解析 tx 的 to/value
- ERC20 转账：解析合约 Transfer 事件的 logs
- 确认策略：等待 finalized 或固定区块数（如 12 个）
- 需处理 reorg：入账前确保区块不会回滚

### 提币系统
流程：用户申请 -> 风控审核 -> 构造交易 -> 签名 -> 广播 -> 监控确认

关键点：
- nonce 需集中管理，不能并发分配
- gas 策略：参考最新 base fee，设置合理 maxFeePerGas
- 广播失败需重试，成功后持续监控 tx 状态

### 签名服务
- 私钥存储：[[05-钱包系统/私钥存储/私钥存储方案概览|方案概览]] | [[05-钱包系统/私钥存储/KMS|KMS]] / HSM / MPC
- 签名服务与业务系统隔离，签名服务不直接接触网络
- 热钱包（在线签名）/ 冷钱包（离线签名）分层管理

### 风控系统
- 黑名单地址过滤
- 单笔/日累计限额
- 异常行为检测（频率、金额突变）
- 大额提币人工审核

## nonce 管理
- 全局唯一，单点分配（不能让多个服务并发获取 nonce）
- 维护 pending 队列，监控每笔 tx 状态
- 发现卡死时自动触发 replace-by-fee 或重发
