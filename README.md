# Web3 Wallet Notes

面向 Web3 钱包工程师的个人知识中枢，用于沉淀学习笔记、技术原理、系统设计、代码阅读结论和面试表达。

本仓库追求的是形成可复用的知识体系，而不是实现一个新的生产钱包服务。

## 仓库定位

- `docs/`：知识主体，包括零碎记录、系统化主题、源码阅读和面试总结。
- `src/`：与文档配套的可运行验证；代码用于证明理解，不追求完整产品形态。
- `api/`：实验项目使用的接口契约。

知识沉淀遵循以下路径：

```text
零碎记录 -> 主题笔记 -> 系统设计 -> 最小实验 -> 面试表达
```

## 内容地图

| 主题 | 内容 |
| --- | --- |
| `docs/ETH/` | Ethereum 基础、交易机制、钱包工程与密钥管理 |
| `docs/Uniswap/` | Uniswap 原理、Swap 系统设计与实施计划 |
| `docs/精通以太坊/` | 《精通以太坊》章节学习总结 |

| `src/swap/docs/` | 与 Swap 实验直接对应的架构图和流程图 |

完整入口见 [docs/README.md](docs/README.md)。

## 记录原则

一篇成熟的主题笔记应尽量回答：

1. 它解决什么问题？
2. 核心原理和关键数据结构是什么？
3. 生产环境中会怎样失败？
4. 常见方案有哪些取舍？
5. 仓库中有哪些代码或实验可以验证？
6. 面试时如何在 1～3 分钟内讲清楚？

零碎想法先放入 `docs/inbox/`，确认和整理后再迁移到对应主题。实验代码必须能对应到一个明确的问题，不为了补齐“完整系统”而扩展。

## 与 Web3 Wallet Labs 的关系

- **Web3 Wallet Notes**：知识入口和最终结论。
- **Web3 Wallet Labs**：钱包技术的小型代码实验，例如 HD Wallet、Gas、交易、扫描和风控。
- 本仓库的 `src/swap/` 暂时保留，因为它与现有 Swap 系统设计文档联系紧密；后续是否迁入 Labs，以避免重复为判断标准。

## 名称迁移

建议 GitHub 仓库最终命名为 `web3-wallet-notes`。当前 Go module 仍使用
`github.com/web3-wallet-org/web3-wallet`，在远程仓库正式重命名之前保持不变，避免本地引用失效。
